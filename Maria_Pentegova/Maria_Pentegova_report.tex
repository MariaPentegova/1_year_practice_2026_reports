\section{Постановка задачи обхода в ширину на разреженных структурах}

Настоящая работа посвящена исследованию эффективности алгоритмов обхода в ширину (\foreignlanguage{english}{Breadth-First Search, BFS}) при обработке больших разреженных графов. Скорость выполнения этого алгоритма определяет общую производительность современных систем интеллектуального анализа данных, социальных сетей и поисковых движков.

В рамках исследования рассматриваются два вычислительных варианта алгоритма: \texttt{parent-BFS} (с фиксацией дерева предков для каждой достижимой вершины) и \texttt{multisource BFS} (параллельный обход из фиксированного множества начальных источников). Реализация алгоритмов выполняется в двух основных вычислительных базисах: линейно-алгебраическом (на базе интерфейса \texttt{SuiteSparse:GraphBLAS}~\cite{graphblas-api}, преобразующего графовые операции в матрично-векторное умножение) и классическом последовательном на C.

В качестве фундаментальной структуры данных для последовательного обхода используется формат сжатого хранения строк (\foreignlanguage{english}{Compressed Sparse Row, CSR})~--- компактный способ представления разреженных матриц смежности графа. Суть структуры \texttt{CSR} заключается в замене ресурсоёмкого двумерного массива (матрицы) на три плоских одномерных массива:
\begin{itemize}
    \item \texttt{row\_ptr} (массив смещений)~--- фиксирует индексы начала и конца списков смежности для каждой строки в общем пуле данных;
    \item \texttt{col\_idx} (массив индексов столбцов)~--- последовательно хранит идентификаторы смежных вершин (целевых узлов ребер);
    \item массив значений ребер (в случае невзвешенных графов данный массив заменяется логическим предикатом существования связи).
\end{itemize}
Такое плотное представление исключает хранение нулевых элементов, минимизирует накладные расходы на адресацию памяти и гарантирует высокую локальность данных при последовательном чтении соседей вершины процессором, что критически важно для обеспечения высокой скорости продвижения фронта обхода.


\section{Разработка низкоуровневых алгоритмов и подсистемы верификации инвариантов}

Программный комплекс реализован в виде независимых модулей с использованием гибридной вычислительной архитектуры на языках C (стандарт C11) и C++ (стандарт C++17) без привлечения высокоуровневых абстракций ООП. Применение компилятора \texttt{g++} позволило эффективно связать низкоуровневые Си-структуры со строгими С++ шаблонами эталонных библиотек. В данном разделе детально описывается низкоуровневое управление структурами данных, алгоритмы продвижения фронта обхода и логика разработанных автоматических тестов.

\subsection{Управление структурами данных и реализация последовательного обхода}

В рамках первого этапа работы в модуле \texttt{utils.c} были разработаны функции динамического управления структурами данных графа. Базовое чтение файлов формата Matrix Market (\texttt{.mtx}) реализовано вручную через функции потокового ввода \texttt{fgets} и \texttt{fscanf}. Поскольку граф является невзвешенным (\texttt{pattern}), ребра обрабатываются как логические связи. Парсер динамически строит граф в виде списков смежности, выделяя память под цепочки узлов \texttt{struct Node} через функцию \texttt{malloc} и вставляя новые элементы в голову списка за время $O(1)$.

Для повышения локальности данных в памяти и ускорения обхода реализована функция \texttt{graph\_to\_csr}, преобразующая списки смежности в плоский формат сжатого хранения строк. Функция выполняет два последовательных прохода по графу:
\begin{itemize}
    \item \textbf{первый проход:} вычисление степеней вершин и заполнение массива смещений \texttt{row\_ptr} накопительной суммой с выделением памяти под результирующий массив \texttt{col\_idx};
    \item \textbf{второй проход:} линейное распределение идентификаторов соседей по ячейкам массива \texttt{col\_idx}. Для бесконфликтной записи используется временный массив счетчиков-смещений, инициализируемый нулями через функцию \texttt{calloc}.
\end{itemize}

Последовательный обход реализован в файле \texttt{classic\_bfs.c}. В качестве структуры данных для управления порядком обхода спроектирована линейная очередь \texttt{queue} на базе плоского динамического массива. Продвижение по очереди контролируется двумя индексами-указателями: \texttt{head} (индекс чтения элемента для обработки соседей) и \texttt{tail} (индекс записи вновь обнаруженных вершин). Добавление элементов в хвост и извлечение из головы выполняются с использованием постфиксного инкремента (\texttt{tail++} и \texttt{head++}).

Массив \texttt{parent} инициализируется значениями $-1$ и выполняет двойную роль:
\begin{enumerate}
    \item хранение идентификатора вершины-первооткрывателя (предка) для восстановления кратчайшего пути;
    \item защитный маркер посещенных вершин (\foreignlanguage{english}{visited}), предотвращающий зацикливание алгоритма.
\end{enumerate}

В алгоритме \texttt{csr\_multisource\_bfs} (\enquote{мультисоурсный обход}) массив очереди \texttt{queue} на этапе подготовки принудительно заполняется идентификаторами всех четырех стартовых источников через цикл \texttt{for}, что моделирует параллельное распространение независимых волн обхода из разных центров до момента их встречи на нейтральных вершинах.

\subsection{Интеграция с линейно-алгебраическим интерфейсом SuiteSparse:GraphBLAS}

Матрично-векторная версия алгоритма обхода реализована в модуле \texttt{graphblas\_bfs.c}. Для переноса топологии графа во внутреннюю структуру библиотеки SuiteSparse используется низкоуровневая функция импорта \texttt{GxB\_Matrix\_import\_CSR}. Импорт выполняется в безопасном режиме со значением флага \texttt{fast\_import = false}. Это заставляет библиотеку принудительно выполнить валидацию переданных массивов и автоматически отсортировать по возрастанию элементы \texttt{col\_idx} внутри каждой строки, компенсируя их изначальное убывающее расположение, вызванное ручной вставкой Си-узлов в голову списка.

Низкоуровневые операции управления очередью и пошаговый перебор смежных вершин в среде \texttt{GraphBLAS} заменены на строгие линейно-алгебраические абстракции над разреженными структурами:
\begin{itemize}
    \item \textbf{Вектор фронта (\texttt{frontier}):} разреженный логический вектор, заменяющий классический массив очереди. Активное состояние ячейки \texttt{true} детерминирует присутствие соответствующей вершины на текущей линии обхода графа;
    \item \textbf{Операция шага (\texttt{GrB\_vxm}):} векторно-матричное умножение вектора текущего фронта на булеву матрицу смежности графа $A$. Расчет производится на базе логического полукольца \texttt{g\_lor\_land\_semiring}, в котором мультипликативная операция заменена на логическое И (\texttt{GrB\_LAND}), а аддитивная~--- на логическое ИЛИ (\texttt{GrB\_LOR});
    \item \textbf{Управление историей посещений:} для отсечения уже пройденных вершин в функцию \texttt{GrB\_vxm} передается инвертированная маска вектора \texttt{visited}. Настройка этого поведения реализована через глобальный дескриптор \texttt{g\_desc\_visited\_comp\_replace}. Параметр аккумулятора функции умножения принудительно выставлен в \texttt{NULL}, что гарантирует получение абсолютно чистого изолированного слоя новых вершин на каждом шаге обхода. Запись вычисленных уровней в результирующий вектор выполняется массовым присвоением через \texttt{GrB\_assign}.
\end{itemize}

\subsection{Изоляция измеряемых факторов алгоритма и интеграция верификационного эталона}

Для обеспечения методологической чистоты эксперимента базовые исследуемые алгоритмы обхода (составляющие вычислительное ядро программного комплекса) были разработаны самостоятельно непосредственно поверх структур \texttt{CSR} и базового ядра библиотеки \texttt{SuiteSparse:GraphBLAS}. Использование готовых высокоуровневых фреймворков и графовых расширений, таких как библиотека \texttt{LAGraph}~\cite{lagraph}, было намеренно исключено на этапе проектирования экспериментального стенда. Высокоуровневые библиотеки содержат внутренние динамические эвристики, включая направление-оптимизированный поиск (\foreignlanguage{english}{direction-optimizing BFS}), автоматическое переключение форматов векторов фронта (между разреженным и плотным представлениями) и специфичные скрытые механизмы предвыборки памяти. Включение таких скрытых факторов в контур тестирования привело бы к смешению измеряемых параметров, делая невозможным корректное сопоставление базовой эффективности самой матрично-векторной концепции с последовательным обходом.

Самостоятельная низкоуровневая реализация алгоритмов на C гарантирует строго эквивалентные стартовые условия запуска для созданного кода и GraphBLAS: единый распределитель памяти, послойное~--- классическое \enquote{ориентированное вперёд}~--- продвижение фронта волны и идентичные критерии останова по пустому вектору. Это позволяет изолировать программные эвристики и оценить чистый вклад линейно-алгебраической модели вычислений.

Для проведения объективной внешней верификации скоростных показателей разработанного в ходе работы ядра в общую систему сборки проекта (\texttt{CMake}) был интегрирован независимый промышленный эталон~--- алгоритм последовательного BFS из библиотеки \texttt{Boost Graph Library}~\cite{boost-graph}. Данный модуль вызывается изолированно, непосредственно в рамках общего цикла бенчмарка, и выполняет роль глобального \foreignlanguage{english}{baseline}-теста. Поскольку \texttt{Boost BGL} представляет собой мировой академический стандарт для вычислений на грахах в среде C++, сопоставление времени работы с этой библиотекой позволяет строго и независимо сертифицировать качество и степень оптимизации созданного Си-кода.

\subsection{Архитектура автоматизированного тестирования}

Для обеспечения стопроцентной надежности программного кода разработана независимая подсистема тестов (каталог \texttt{src/tests}), управляемая встроенным в CMake механизмом \texttt{enable\_testing()}. В файле \texttt{test\_utils.c} реализованы функции генерации жестко зашитого в памяти эталонного графа из 5 вершин и матрицы расстояний \texttt{expected}.

Валидация кодовой базы опирается на системные макросы \texttt{assert(...)} и разделена на три изолированных этапа проверки инвариантов:
\begin{enumerate}
    \item \textbf{Проверка связности дерева предков (\texttt{test\_classic\_bfs.c}):} автоматически проверяется, что стартовый корень строго указывает сам на себя, все достижимые вершины избавлены от значения $-1$, а у промежуточных вершин отсутствуют изолированные циклические петли на самих себя;
    \item \textbf{Перекрестное побитовое сравнение (\texttt{test\_comparison.c}):} результаты выполнения последовательного обхода на очередях из \texttt{classic\_bfs.c} поэлементно сравниваются с результатами работы векторных функций GraphBLAS. Любое расхождение в вычисленных уровнях или предках приводит к мгновенной аварийной остановке теста;
    \item \textbf{Тестирование мультисоурсного инварианта (\texttt{test\_graphblas\_bfs.c}):} проверяется математический закон графов, согласно которому расстояния до вершин при множественном старте обязаны быть строго меньше или равны расстояниям при одиночном старте (\texttt{level[i] <= level\_single[i]}).
\end{enumerate}

\textbf{Влияние топологии графа на границы применимости подходов.}
Анализ данных в таблице~\ref{tab:results} чётко выявляет границы применимости подходов, продиктованные структурой связности данных:

В этих условиях линейно-алгебраический подход (\texttt{GB-L}) раскрывает свой потенциал, опережая классику до 3.91 раза. Операция \texttt{GrB\_vxm} на булевом полукольце эффективно распараллеливается на уровне векторных инструкций процессора (\texttt{AVX/SSE});
    \item \textbf{Длинные цепочечные структуры и направленные графы} (\texttt{roadNet-CA}, \texttt{road\_usa}, \texttt{cit-Patents}, \texttt{web-Google}). Характеризуются низким средним числом связей и огромным диаметром. На таких структурах \texttt{GraphBLAS} уступает созданному в ходе работы C-коду до 73.71 раза (в режиме мультипоиска на \texttt{road\_usa}). Накладные расходы SuiteSparse на вызовы функций, управление масками и пошаговый динамический менеджмент памяти под разреженные векторы фронтов на порядки превышают время полезных вычислений. Дополнительным фактором замедления \texttt{GraphBLAS} на графах с большим числом вершин (\texttt{cit-Patents}) выступает неоптимальная поштучная выгрузка уровней через \texttt{GrB\_Vector\_extractElement} внутри цикла.
\end{itemize}

\textbf{Сертификация и верификация качества разработанного кода.}
Для независимой оценки качества и подтверждения высокой оптимизации разработанного последовательного ядра был проведён обособленный верификационный тест. Разработанный код спроектирован непосредственно поверх плоских одномерных массивов с принудительным использованием компактного 32-битного типа \texttt{int}, что обеспечило высокую локальность кэш-памяти процессора (\texttt{L1/L2 Cache}) и максимальное быстродействие.


\section{Заключение}

В ходе выполнения настоящей работы были успешно решены все поставленные задачи и получены следующие основные результаты:
\begin{itemize}
    \item на языке C (стандарт C11) реализованы четыре варианта алгоритма обхода в ширину, базирующиеся на классическом последовательном подходе (\texttt{CSR}) и линейно-алгебраическом подходе на основе библиотеки \texttt{SuiteSparse:GraphBLAS};
    \item спроектирована модульная инфраструктура автоматизированного тестирования, обеспечивающая перекрёстную валидацию результатов и проверку топологических инвариантов дерева предков, что гарантирует полную логическую корректность разработанного программного обеспечения (\enquote{100\% passed});
    \item проведены детальные экспериментальные замеры времени выполнения обхода на семи реальных крупномасштабных графах различной направленности (ориентированные графы веб-ссылок и цитирований, неориентированные социальные и дорожные сети) из коллекции \texttt{SuiteSparse Matrix Collection};
    \item на основе полученных эмпирических данных выявлены и обоснованы границы применимости исследуемых подходов. Доказано, что применение \texttt{GraphBLAS} обеспечивает ускорение вычислений до 3.91 раза на неориентированных социальных сетях с малым диаметром за счёт эффективных внутренних векторных оптимизаций SuiteSparse на крупных фронтах. Напротив, для дорожных сетей и сильно разреженных ориентированных иерархических структур последовательный обход на структурах \texttt{CSR} демонстрирует безусловное преимущество (до 73.71 раза), поскольку накладные расходы библиотеки на разреженных фронтах малой размерности превышают время полезной работы;
    \item \textbf{экспериментально подтверждена высокая эффективность и оптимизированность созданной в ходе работы кодовой базы на языке C}~--- за счёт использования компактных 32-битных типов данных, прямой работы с памятью и отсутствия избыточных шаблонов С++ абстракций разработанный алгоритм уверенно обошёл официальный индустриальный эталон \texttt{Boost Graph Library} на всех типах исследованных топологий в $1.5\sim17.12$ раза.
\end{itemize}
